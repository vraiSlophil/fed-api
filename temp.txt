## 1️⃣ Modèle relationnel proposé

```sql
-- Utilisateurs ------------------------------------------------------------
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    uuid BINARY(16) NOT NULL UNIQUE,            -- pour une interop future
    pseudo VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    avatar_path VARCHAR(255) NULL,
    nom  VARCHAR(100),
    prenom VARCHAR(100),
    last_login_at DATETIME NULL,
    last_login_ip VARCHAR(45) NULL,             -- IPv4 / IPv6
    settings JSON NULL,                         -- préférences d’affichage, thèmes favoris…
    role ENUM ('user','admin') DEFAULT 'user',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- Historique de connexions ------------------------------------------------
CREATE TABLE user_logins (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNSIGNED NOT NULL,
    logged_at DATETIME NOT NULL,
    ip VARCHAR(45) NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX (user_id, logged_at)
);

-- Historique de profil (audit) -------------------------------------------
CREATE TABLE user_profile_histories (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNSIGNED NOT NULL,
    changed_at DATETIME NOT NULL,
    changer_id BIGINT UNSIGNED NULL,            -- qui a modifié (self ou admin)
    before_state JSON,
    after_state  JSON,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX (user_id, changed_at)
);

-- Thèmes ------------------------------------------------------------------
CREATE TABLE themes (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    uuid BINARY(16) NOT NULL UNIQUE,
    owner_id BIGINT UNSIGNED NOT NULL,
    title VARCHAR(150) NOT NULL,
    color CHAR(7) NOT NULL,                     -- #RRGGBB
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (owner_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX (owner_id),
    FULLTEXT INDEX ft_theme_title (title)       -- recherche texte
);

-- Partage (invités) -------------------------------------------------------
CREATE TABLE theme_user (
    theme_id BIGINT UNSIGNED NOT NULL,
    user_id  BIGINT UNSIGNED NOT NULL,
    invited_at DATETIME NOT NULL,
    status ENUM('active','revoked') DEFAULT 'active',
    PRIMARY KEY (theme_id, user_id),
    FOREIGN KEY (theme_id) REFERENCES themes(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id)  REFERENCES users(id)  ON DELETE CASCADE,
    INDEX (status)
);

-- Historique de thèmes ----------------------------------------------------
CREATE TABLE theme_histories (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    theme_id BIGINT UNSIGNED NOT NULL,
    changed_at DATETIME NOT NULL,
    changer_id BIGINT UNSIGNED,
    change_type ENUM('title','color','share','delete'),
    before_state JSON,
    after_state  JSON,
    FOREIGN KEY (theme_id) REFERENCES themes(id) ON DELETE CASCADE,
    INDEX (theme_id, changed_at)
);

-- Tâches ------------------------------------------------------------------
CREATE TABLE tasks (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    uuid BINARY(16) NOT NULL UNIQUE,
    theme_id BIGINT UNSIGNED NOT NULL,
    creator_id BIGINT UNSIGNED NOT NULL,
    title VARCHAR(255) NOT NULL,
    status ENUM('todo','doing','done') DEFAULT 'todo',
    validated_at DATETIME NULL,                 -- coche
    archived_at DATETIME NULL,                  -- « cardbox »
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (theme_id)   REFERENCES themes(id) ON DELETE CASCADE,
    FOREIGN KEY (creator_id) REFERENCES users(id)  ON DELETE SET NULL,
    INDEX (theme_id),
    INDEX (status),
    INDEX (archived_at)
);

-- Historique de tâches ----------------------------------------------------
CREATE TABLE task_histories (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    task_id BIGINT UNSIGNED NOT NULL,
    changed_at DATETIME NOT NULL,
    changer_id BIGINT UNSIGNED,
    before_state JSON,
    after_state  JSON,
    FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE,
    INDEX (task_id, changed_at)
);
```


Relations principales :

* users 1─∞ themes   (owner)
* users 1─∞ tasks    (creator)
* themes 1─∞ tasks
* themes ∞─∞ users via theme_user (partage)
* Tables d’historique liées par clé étrangère pour un audit complet.

## 2️⃣ Gestion optimale des fichiers avatar

1. **Filesystem abstrait** : utiliser le `Storage` Laravel (driver `local`, `s3`, `wasabi`, etc.).
2. **Répertoire « sharding »** : `/avatars/{first2chars_uuid}/{uuid}.jpg` pour éviter des milliers de fichiers dans un même dossier.
3. **Versions redimensionnées** : générer à l’upload (ex. 40 px, 160 px) et stocker le chemin dans `avatar_path` ou dans `settings->avatar_sizes`.
4. **Cache HTTP + CDN** : servir les images via un CDN ou CloudFront pour soulager le serveur PHP.
5. **Suppression différée** : un job de queue `DeleteOldAvatar` supprime physiquement l’ancien fichier après confirmation de la mise à jour.
6. **Validation & sécurité** : limiter la taille (ex. 512 Ko), le type MIME, et passer l’image dans `Image::orientate()` (Intervention) pour éviter les images piégées.

## 3️⃣ Index pertinents

Table      | Index                                                                   | Pourquoi
-----------|-------------------------------------------------------------------------|----------
users      | UNIQUE(pseudo), UNIQUE(email)                                           | login & recherche
users      | INDEX (last_login_at)                                                   | stats d’activité
themes     | INDEX(owner_id, created_at DESC)                                        | tableau de bord de l’utilisateur
themes     | FULLTEXT(title)                                                         | recherche par titre
theme_user | INDEX(status)                                                           | filtrer les partages actifs
tasks      | INDEX(theme_id, status)                                                 | colonne Kanban par thème
tasks      | INDEX(theme_id, archived_at)                                            | accès rapide à la cardbox
tasks      | FULLTEXT(title)                                                         | recherche rapide de tâche
task_histories | INDEX(task_id, changed_at DESC)                                     | fil d’activité
user_logins| INDEX(user_id, logged_at DESC)                                          | page « Dernières connexions »

NB : Sous MariaDB 11, un FULLTEXT sur `VARCHAR(255)` en `InnoDB` est OK.

## 4️⃣ Préparer l’avenir

1. **UUID natifs** : garder un `BINARY(16)` `uuid` en plus de l’`AUTO_INCREMENT` pour un découplage si un jour on passe en micro-services.
2. **Colonnes JSON** : `settings`, `before_state`, `after_state` accueillent de nouveaux paramètres sans migration immédiate.
3. **Soft Deletes** : utiliser `archived_at` plutôt que `is_archived TINYINT(1)`. L’avantage : date + possibilité d’index.
4. **Évènements de domaine** : `TaskCreated`, `TaskArchived`, `ThemeShared` publiés dans la queue → facile d’ajouter des webhooks ou des notifications.
5. **Versionnage de schéma** : migrations Laravel + tests de régression (PHPUnit) pour sécuriser tout ajout.
6. **Normalisation modérée** : conserver des tables d’historique séparées (plutôt qu’une table globale) pour éviter la scalarisation prématurée et faciliter des évolutions (ex. export CSV spécifique, purge sélective).
7. **Abstraction “media”** : si demain on veut stocker des fichiers dans les tâches, prévoir une table polymorphe `media` (id, mediable_type, mediable_id, path, type, size…).

### ➕ Bonus : Exemple d’Eloquent

```php
// Theme.php
class Theme extends Model
{
    use HasFactory;

    protected $fillable = ['title', 'color'];

    public function owner()   { return $this->belongsTo(User::class, 'owner_id'); }
    public function tasks()   { return $this->hasMany(Task::class); }
    public function members() { return $this->belongsToMany(User::class)
                                           ->withPivot(['invited_at','status'])
                                           ->using(ThemeUser::class); }
}
```


Ce design reste performant, respecte vos besoins actuels et offre une marge de manœuvre confortable pour les prochaines fonctionnalités.
